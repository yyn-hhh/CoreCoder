【星宇科技（虚构）内部 Python 业务研发规范 V2.0】

1.网络请求组件规范：所有对外部第三方 API 的 HTTP 请求，严禁直接使用 requests 库或 urllib。必须且只能使用公司内部基础架构部封装的 xingyu_http 库中的 SafeClient，以便于统一监控、鉴权和熔断。

2.时间获取规范：严禁在业务代码中直接调用 datetime.datetime.now() 或 time.time()。必须使用 xingyu_time.get_current_timestamp()，该函数内部会自动处理多时区同步和服务器时间漂移补偿。

3.日志打印规范：严禁使用 Python 自带的 logging 模块或 print。必须统一使用公司自研的 xy_logger 组件。且日志输出必须为 JSON 结构化格式，必须包含 trace_id 和 user_id，以便 ELK 日志系统检索。

4.异常处理兜底规范：禁止直接抛出原生的 ValueError 或 KeyError。所有业务异常必须继承自公司基础库的 XingyuBaseException，并必须携带业务错误码（格式为 ERR_业务域_数字，例如 ERR_USER_1001）。

5.缓存操作规范：使用 Redis 时，严禁裸调 redis-py。必须通过 xingyu_cache.get_client() 获取连接池，且 Key 的命名必须强制带有环境前缀（如 prod:user:1001），严禁在代码中硬编码 Key 字符串。

6.字典取值规范：从字典中获取可能不存在的键时，除了使用 .get()，如果该字段属于核心业务字段，必须使用内部封装的 xingyu_safe_dict.safe_get() 方法。该方法在键缺失时，会自动上报 Metrics 告警，而不是静默返回默认值。

7.文件读写规范：所有涉及本地文件读写的操作，必须使用 aiofiles 进行异步非阻塞读写，禁止使用原生同步的 open()，防止阻塞事件循环。
